# Dashboard design notes (phase MF9a)

The dashboard is a static React + TypeScript app in `web/`, built with Vite, deployed to
GitHub Pages. It reads only the JSON files in `web/public/data/`, generated from the real
MRA and Census tables by `make webdata` — no synthetic data appears anywhere in it.

## Palette validation

The categorical palette (`web/src/styles.css`) reuses the same eight-hue, CVD-safe order as
the static figures in `results/figures/` (`src/kisti/analysis/style.py`), so a colour means the
same thing in the notebook-style report and in the dashboard. It was checked with the dataviz
skill's validator:

```
node scripts/validate_palette.js "#2a78d6,#eb6834,#1baf7a,#eda100,#e87ba4,#008300" --mode light
node scripts/validate_palette.js "#3987e5,#d95926,#199e70,#c98500,#d55181,#008300" --mode dark
```

Result (adjacent pairs, the relevant test for a stacked bar): all six slots pass the lightness
band, chroma floor, and CVD/normal-vision separation floors in both modes (light: worst CVD ΔE
9.1, worst normal-vision ΔE 19.6; dark: worst CVD ΔE 8.4, worst normal-vision ΔE 19.3). In light
mode, three slots (aqua, yellow, magenta) fall under the 3:1 contrast floor against the surface
and trigger the relief rule — every chart that uses more than two series (only the funding-mix
stacked bars do) pairs colour with a visible value label on every segment wide enough to hold
one, and the full numbers are always in the table underneath. Dark mode clears 3:1 on all six
without relief.

## What is static vs computed in the browser

Most figures reproduce a table already in `sector.json`, generated by `kisti.analysis` and
checked against RESULTS.md by `tests/test_analysis_results.py`. Two exceptions compute directly
from `mfis.json` (the per-MFI export) in the browser, documented in `src/lib/bands.ts`:

- the efficiency and outreach range charts (median and interquartile range by size band), since
  `kisti.analysis.efficiency`/`outreach` only publish the medians RESULTS.md quotes, not the
  full distribution; and
- the yield histogram and the yield-vs-OSS scatter, which need the raw per-MFI values.

Both are ordinary descriptive statistics (median, quartiles) on fields already present, tested
in `src/lib/stats.test.ts` and `src/lib/bands.test.ts`.

## The data contract

`src/kisti/webdata/schema.py` and `web/src/lib/schema.ts` list the same fields by hand for
`meta`, `mfis` and `districts`. `tests/test_webdata.py` checks the committed JSON against the
Python schema; `web/src/lib/schema.test.ts` checks the same files against the TypeScript one.
Neither test reads the other's schema file, so an unnoticed rename shows up as a failure on at
least one side. `loadAppData` (`web/src/lib/data.ts`) re-checks both at runtime, so a stale
build serving a JSON export from a different schema version fails loudly in the browser instead
of silently mis-rendering.

## Accessibility

- Every chart with two or more series has a legend; a single-hue chart does not, per the
  dataviz skill (a lone series' identity is already given by the chart's title).
- Every `HorizontalBars` chart carries a visually-hidden `<table>` with the same values, for
  screen readers and as a plain-text fallback. That table lives in a wrapping `<div
  class="sr-only">`, not directly on the `<table>` — a `<table>` under automatic layout ignores
  an explicit narrow `width` (its content's minimum width wins), so the clipping box has to be
  the wrapping div. `HorizontalBars` also shortens any label that would not fit its column,
  since SVG text does not wrap and would otherwise render past the chart's left edge and be
  clipped there; the full text stays available via a native `<title>`, the hover tooltip and
  that same accessible table.
- The tab list follows the WAI-ARIA tabs pattern (roving tabindex, arrow-key navigation).
- Every `DataTable` is a real HTML table with sortable, keyboard-operable column headers
  (`aria-sort`), and doubles as the "table view" for any chart it sits beside.
- Colour theme (light/dark/auto) is a real toggle, not just the OS setting, and is remembered
  per browser via `localStorage` (wrapped in try/catch, since a private window or blocked site
  data can make it throw or come back empty).

## Layout

Checked at 375px width (phone) and 1280px (desktop) with no horizontal page scroll at either.
Every chart's SVG caps its own `max-width` to its designed pixel size and scales down on
narrower screens, rather than stretching to fill an arbitrarily wide card.
